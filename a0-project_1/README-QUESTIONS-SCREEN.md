# Research Questions Screen Implementation

This document outlines the implementation of the dedicated Research Questions Screen, which allows users to view and answer research questions without affecting the existing functionality of the application.

## Overview

The new `ResearchQuestionsScreen` provides a dedicated interface for answering research questions, separate from the chat interface. This screen:

1. Displays questions fetched from Supabase based on the research ID
2. Allows users to submit answers to all questions at once
3. Maintains real-time monitoring for new questions
4. Sends answer data back to the webhook URL
5. Updates the Supabase database with answers

## Testing the Implementation

### Option 1: Direct Testing with Test Screen

1. Launch the app
2. The app will open on the `TestQuestionsSubmissionScreen`
3. Run the test script to generate test data:
   ```bash
   node a0-project/test-questions-submission.js
   ```
4. Copy the generated research ID from the terminal
5. Paste it into the "Research ID" field on the test screen
6. Click "Go to Questions Screen" to navigate to the questions screen
7. Answer the questions and click "Submit All Answers"
8. Check the terminal for real-time updates confirming the submission

### Option 2: Testing through Normal Flow

1. Launch the app 
2. Navigate to the Research Parameters screen
3. Enter a research query and other parameters
4. Submit the query
5. The app will navigate to the new Research Questions Screen
6. Answer the questions and submit them
7. The app will automatically navigate back after successful submission

## Structure and Files

- `ResearchQuestionsScreen.tsx`: The main component for displaying and submitting research questions
- `test-questions-submission.js`: Script to generate test data in Supabase and monitor for changes
- `TestQuestionsSubmissionScreen.tsx`: A test interface for direct testing

## Implementation Details

### Navigation Flow

1. When a user submits a research query in `ResearchParametersScreen`, the app now navigates to `ResearchQuestionsScreen` instead of `ResearchChatScreen`
2. After submitting answers, the app navigates back

### Data Flow

1. Questions are fetched from Supabase using the `fetchQuestions` function in `questionsManager.ts`
2. Real-time monitoring is set up to detect new questions using `monitorQuestions`
3. Answers are submitted using `submitAllAnswers`, which:
   - Updates the Supabase database
   - Sends the answers to the webhook URL if provided

### Features

- Real-time updates: The screen automatically updates when new questions are added
- Batch submission: All answers are submitted together with one button
- Error handling: Proper error states and retries
- Loading states: Visual feedback during loading and submission
- Success confirmation: Success message after submission

## Troubleshooting

If questions are not displaying or submissions are failing:

1. Check the research ID format - it should match the format generated by the test script
2. Verify that Supabase is accessible and properly configured
3. Check for any console errors in the terminal or device logs
4. Try running the test script again to generate fresh test data

## Integration Notes

- The implementation maintains backward compatibility with the existing webhook system
- No changes were made to the existing `questionsManager.ts` functionality
- The screen seamlessly integrates into the existing navigation flow
- The UI follows the same theme and design language as the rest of the app
